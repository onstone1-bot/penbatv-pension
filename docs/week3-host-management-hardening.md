# 펜바TV 3주차 15~21일차 개발 정리 - 사장님 관리 실데이터화

## 이번 차수 목표

사장님 관리화면에서 숙소, 객실, 사진, 영상, 네이버 링크, 주변 맛집/가볼만한곳을 등록하거나 수정할 때 실제 DB에 반영되고, 운영자가 나중에 변경 이력을 확인할 수 있도록 감사 로그를 추가했다.

## 추가된 DB 테이블

### host_operation_events

사장님 또는 운영자가 관리화면에서 수행한 변경 이력을 저장한다.

주요 컬럼:

- actor_role: host 또는 operator
- actor_user_id: 로그인 사용자 ID가 있을 경우 저장
- accommodation_id: 대상 숙소 ID
- room_id: 대상 객실 ID
- target_type: accommodation, room, room_image, room_rate, booking_option, youtube_campaign, naver_link, nearby_place
- target_id: 변경 대상 고유값
- action: create, update, hide, upsert, set_cover
- metadata: 변경 내용 요약 JSON
- created_at: 발생 시각

## 왜 필요한가

초기에는 사장님이 직접 정보를 넣는 구조가 중요하다. 그런데 실제 서비스가 되면 “누가 가격을 바꿨는지”, “대표사진을 언제 바꿨는지”, “유튜브 링크가 어떤 객실에 연결됐는지”를 확인해야 한다. 이 테이블은 향후 운영자 관리화면의 변경이력 탭, 분쟁 대응, QA 리포트의 기반이 된다.

## 검증 방법

로컬 서버 실행 후 아래 명령으로 3주차 흐름을 점검한다.

```bash
npm run verify:week3:host
```

검증 항목:

- 숙소 기본정보 수정
- 객실 생성, 수정, 숨김
- 객실 대표사진 등록
- 바베큐 옵션 등록
- 유튜브 링크 등록
- 네이버 블로그/리뷰 등록
- 주변 맛집/가볼만한곳 등록
- 각 변경사항의 host_operation_events 로그 생성

## 현재 상태

3주차 기능은 실제 API와 Supabase DB 기준으로 검증 가능하다. 다만 사장님 로그인 계정별 권한 연결은 4주차 회원/권한 단계에서 더 정교하게 연결해야 한다.
