# 펜바TV 웹앱 아키텍처 및 런칭 가이드

일자: 2026-08-15

## 개발 방향

펜바TV는 유튜브 영상을 먼저 보고 예약으로 이어지는 펜션 광고/예약결제 플랫폼이다. 초기 MVP는 직접 코딩 가능한 Next.js와 Supabase 기반으로 진행하고, 결제는 Toss Payments 결제창/승인 API, 정산은 별도 지급대행 또는 정산 대사 모듈로 분리한다.

## 추천 기술 스택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프론트엔드 | Next.js App Router | `천안 펜션`, `광덕계곡 펜션` 같은 지역 SEO와 동적 상세 페이지 운영에 적합 |
| UI | CSS 우선, 추후 Tailwind 전환 | 현재 시안 속도를 유지하고 디자인 토큰이 안정되면 Tailwind로 정리 가능 |
| 백엔드/DB | Supabase PostgreSQL | 예약 가능 여부, 객실, 캠페인, 결제/정산 데이터를 관계형으로 관리 |
| 결제 | Toss Payments | 결제창, 결제 승인, 웹훅, 정산 조회/지급대행 확장 가능 |
| 영상 | YouTube 링크 임베드 | 사장님이 링크를 입력하면 상세 페이지 상단 영상 배너에 자동 반영 |

## 핵심 구현 구조

1. 펜션 입점 등록
   - 펜션명, 지역, 주소, 대표자, 연락처, 광고 상품, 예약 방식, 수수료율 입력
   - 유튜브 링크와 영상 제목 입력
   - 등록 즉시 미리보기와 예약 화면 링크 생성

2. 상세 페이지 자동 업데이트
   - `/stays/[id]` 동적 라우팅 사용
   - DB 또는 mock 데이터에서 slug 기반으로 숙소 정보 조회
   - 유튜브 링크가 있으면 iframe 플레이어 표시
   - 링크가 없으면 `펜바TV 단독 촬영 영상` 배너 표시

3. 예약/결제
   - 예약요청: 운영자 확인 후 결제 링크 발송
   - 바로결제: 예약 가능 여부 확인 후 15분 선점, 결제 준비 API 호출
   - 결제 완료 후 성공/실패 페이지로 복귀

4. 정산
   - 결제 승인과 사장님 지급을 분리
   - 정산 데이터는 `payment_orders`, `payments`, `settlements`로 대사
   - 지급대행은 셀러 등록, 잔액 조회, 지급 요청, 웹훅 처리 모듈로 별도 확장

## 콘텐츠 런칭 플랜

| 단계 | 유튜브 콘텐츠 | 웹앱 개발 |
| --- | --- | --- |
| 현재~1개월차 | 천안·아산 힐링 펜션 3곳 섭외 및 무료 촬영/편집 | DB 구조 설계, 예약 가능 여부, Toss 결제/정산 분리 설계 |
| 2~3개월차 | 영상 순차 업로드 및 지역 타깃 홍보 | 파트너 등록 폼, 자동 상세 템플릿, 관리자 예약함 완성 |
| 오픈 시점 | 고정 댓글/설명란에 펜바TV 예약 링크 연결 | 웹앱 정식 오픈, 예약요청/바로결제/정산 검증 |

```text

/host/launch-plan     개발/런칭 가이드
```

## 사장님 입력 UX

### 성수기 요금

사장님이 직접 날짜 숫자를 입력하는 방식보다 달력에서 기간을 드래그하는 방식이 적합하다.

- 달력에서 2026-07-15부터 2026-08-15까지 드래그
- 기간명을 `여름 성수기`로 입력
- 평일 요금과 주말 요금 입력
- `room_rates` insert preview 확인
- 내부 계산에서는 평일/주말 일수를 나누어 금액을 보여준다

현재 `room_rates` 구조에서는 평일 요금을 `nightly_price`, 주말 추가금을 `weekend_extra`로 저장한다. 추후 요일별 세부 요금이 필요하면 `rate_calendar_days` 또는 `room_rate_weekday_overrides` 테이블로 분리한다.

### 바베큐 옵션

초기 기본값은 `세트당 정액제`가 좋다. 숯, 그릴, 집게, 토치처럼 한 번 준비되는 비용은 사장님이 이해하기 쉽고 고객도 결제 전에 납득하기 쉽다.

다만 다음 옵션은 `1인당 과금`도 지원한다.

- 조식
- 수건/침구 추가
- 체험 프로그램
- 인원별 소모품

### 외부 달력 연동

초기 버전에 포함한다. 단, 네이버/야놀자 정식 양방향 API부터 시작하지 않고 iCal 가져오기 전용으로 시작한다.

- 외부 채널 iCal URL 등록
- 30분 단위 동기화
- 외부 예약을 `room_blocks`로 반영
- 펜바TV 예약 가능 여부 계산에서 외부 예약 차단 반영
- 채널별 정식 API는 제휴 문서 확보 후 양방향 연동으로 확장

## 결제/정산 주의사항

- Toss Payments 결제 API는 Basic 인증과 idempotency key를 사용한다.
- 결제창 방식은 `checkout.url` 또는 SDK `requestPayment()` 흐름으로 연결한다.
- 정산 조회는 결제 다음 날부터 조회 가능하며, 대량 조회는 page/size를 사용한다.
- 지급대행은 추가 계약과 JWE 암호화가 필요하므로 MVP 결제 승인과 분리해 설계한다.
- 가상계좌나 비동기 결제수단은 웹훅으로 상태 변경을 받아야 한다.
